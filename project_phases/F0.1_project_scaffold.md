# F0.1 — Project Scaffold: Implementation Plan

> Phase 0 — Foundations. Source: `project_plan.md`.

---

## Decision (D1): Styling approach — **Tailwind CSS** ✅ (confirmed 2026-04-16)

- **Why Tailwind:** mobile-first responsive utilities map cleanly to the "design tokens" goal in F0.4 (palette/typography/spacing live in `tailwind.config`), tree-shaking keeps the bundle small (matches the performance principle), and it has first-class Next.js App Router support.
- **Why not CSS Modules:** more boilerplate per component; design tokens have to be re-plumbed via CSS variables; less leverage for the rapid, single-page UI being built.
- **Tradeoff:** utility-class HTML can look noisy. Mitigated by extracting repeated patterns into components (which would happen anyway).

- **Commit:** `chore: initialize next.js app router project with typescript`

### 2. Folder structure

```
src/
  app/                 # routes (single page lives here)
    layout.tsx
    page.tsx
    globals.css
  components/          # reusable UI components
  lib/                 # utility functions, constants
  data/                # typed wrappers around /public GeoJSON (later)
  styles/              # design tokens / shared CSS (if needed)
public/
  data/                # GeoJSON files (later phases)
```

- **Commit:** `chore: establish src/ folder structure`

- Keep Next.js's default ESLint config; add Prettier (`prettier`, `eslint-config-prettier`) so they don't fight.

- Add `format` and `lint` scripts to `package.json`.
- **Commit:** `chore: add prettier and align with eslint`
