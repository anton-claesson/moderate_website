# F0.2 — Vercel Deployment Pipeline: Implementation Plan

> Phase 0 — Foundations. Source: `project_plan.md`.

---

## Context
F0.1 delivered the project scaffold on `main`. F0.2 wires it to Vercel so that:
- Every PR gets an isolated preview URL (for visual review before merging)
- Merging to `main` triggers an automatic production deploy
- A lightweight CI gate (lint + type-check + build) blocks bad pushes from deploying

No Vercel config, GitHub Actions, or `.env.example` currently exists. The repo is already connected to GitHub at `git@github.com:jonahaag/moderate_website.git`.

## Implementation Steps

### Step 1 — Connect repo to Vercel (manual, one-time)
This cannot be automated via code. Document in README, then the user must do:
1. Go to vercel.com → Add New Project → Import `jonahaag/moderate_website`
2. Framework: Next.js (auto-detected)
3. Build command: `npm run build` (default)
4. Output directory: `.next` (default)
5. Set env var `NEXT_PUBLIC_MAPBOX_TOKEN` as a placeholder (empty string is fine for now)
6. Deploy — confirm production URL works
7. Confirm preview deploys are enabled (Vercel default: on for all branches/PRs)

### Step 2 — Add `.env.example`
Document all future env vars so contributors know what to add in `.env.local` and what must be set in the Vercel dashboard.

**File: `.env.example`**
```
# Mapbox GL JS public token (required for F2.1)
# Get one at https://account.mapbox.com/
NEXT_PUBLIC_MAPBOX_TOKEN=

# Form backend (required for F5.2 — provider TBD)
# FORM_API_KEY=
```

### Step 3 — Add GitHub Actions CI workflow
Runs on every push to any branch and every PR. Blocks merge if lint, type-check, or build fails. This prevents broken code from reaching Vercel.

**File: `.github/workflows/ci.yml`**
```yaml
name: CI

on:
  push:
    branches: ['**']
  pull_request:
    branches: ['**']

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
      - run: npm ci
      - run: npm run lint
      - run: npm run format:check
      - run: npm run build
```

No separate type-check script needed — `next build` already fails on TypeScript errors with `strict: true`.

### Step 4 — Add minimal `vercel.json`
Only needed to explicitly document the framework. Not strictly required (auto-detected), but makes the config explicit and version-controlled.

**File: `vercel.json`**
```json
{
  "framework": "nextjs"
}
```

### Step 5 — Update `README.md`
Replace the create-next-app boilerplate with project-specific content:
- Project description (one paragraph)
- Local dev setup (`npm install` + `.env.local` setup + `npm run dev`)
- Deployment section: how Vercel auto-deploys from `main`, preview deploys on PRs
- Env vars reference (point to `.env.example`)
